# Discussion — Matching model and effort to the task

This short discussion appears between exercises 3 and 4. Open the
[interactive slide](../../presentation/index.html#dial-practice), or use these identical cases.
No model call is needed. Read the result and choose your first move; change one thing at a time.

## 1. Wikipedia classification

Starting position: **First-best model, Low effort**.

> You, the researcher, want to classify Wikipedia pages for a project on long-term economic growth: which pages describe a technology or a reusable idea? You have three labels: L (likely a technology), U (uncertain) and N (not a technology). You supply each page’s title and introduction to the model and need one label per page. The labels pass a human-checked pilot. But obvious cases still trigger repeated reconsideration by the model. Lower effort has already been tried. What is your next move?

## 2. Polish a regression table

Starting position: **Second-best model, High effort**.

> We are correcting column headings and decimal alignment in a regression table. The agent starts redesigning the table generator and proposing extra tests. What is your next move for a similar task?

## 3. Check a theory section as a referee

Starting position: **Third-best model, High effort**.

> You are reviewing a paper as a referee and doubt the claims in its theory section. You brainstorm back and forth with your model of choice. Even after a retry at high effort, the LLM produces derivations that rest on assumptions the paper’s model does not satisfy, and it does not notice. Which parameter should you change?

## Optional discussion answers

Read after choosing your first move. These are illustrative judgements, not measured rankings of models.

1. Try a smaller model on the same human-checked pilot; retain it only if quality holds. Lower effort has already been tried.
2. Lower effort and set a clear stopping point: headings and alignment, one check, no further changes. A smaller model is also plausible, but effort addresses the observed overrun directly.
3. Switch to a stronger model at its default effort and check each assumption yourself. Repeating high effort has not resolved this capability gap.
